# ADR-0005: 読み上げをメディアセッションとして扱い、連続再生を build の外で進める

- ステータス: 採択
- 日付: 2026-11
- 範囲: フォーク Novelty-local のみ

## 背景

運転中に、画面を見ずに小説を聴きたい。そのためには、ハンドルのボタンでの操作、ナビ・電話との譲り合い、
画面を消したままの継続、作品をまたいだ連続再生が要る。

## 決定

1. audio_service（メディアセッション・通知・Android Auto・フォアグラウンドサービス）と
   audio_session（音のフォーカス・Bluetooth の切断）を使う。
2. 判断の規則は端末に依存しない `ReadAloudRemote` に置き、テストで固定する。
   `ReadAloudController` は静的フックで「読み始めた・片付けた」を知らせるだけにする。
3. フォアグラウンドサービスを途中で切らさない。
   - 一時停止中も保つ（`androidStopForegroundOnPause: false`）。
   - 話・作品の切り替わりでは、45秒間「再生中」のまま待つ。
4. 連続再生では、次の作品の読み込みと読み上げの開始を、画面のコールバックの中（build の外）で行う。
5. `MainActivity` を `AudioServiceActivity` にし、`VoicevoxBridge` はアプリ全体で1つにする。

## 理由

- Android 12 以降、アプリが裏にいる間はフォアグラウンドサービスを新しく始められない。いったん idle にすると、
  画面が消えたまま次の話へ進めなくなる。
- 画面が消えている間、Flutter はフレームを作らず build が走らない。build の中で読み上げを作ると、連続再生が止まる。

## 結果

- 端末連携の層（`read_aloud_media.dart`）は自動テストが無く、実機で確かめる必要がある。
- Android Auto は、Play ストア以外から入れたアプリを既定では表示しない（開発者向けの設定で「提供元不明のアプリ」を許可する必要がある）。
