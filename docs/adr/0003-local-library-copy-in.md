# ADR-0003: ローカル本棚は、テキストをアプリ内に複製して持つ

- ステータス: 採択
- 日付: 2026-11
- 範囲: フォーク Novelty-local のみ

## 背景

端末内の .txt を本棚として読みたい。元のファイルは、ダウンロードフォルダ・SD カード・同期アプリのフォルダなど、
アプリの外にばらばらに置かれている。

## 決定

1. 取り込み時に本文を UTF-8 に正規化し、`local_library/texts/<id>.txt` に複製する。元のファイルは読むだけで変えない
   （UTF-8 への書き直しは、利用者が明示的に有効にしたときだけ行う）。
2. 作品 ID はファイル名の FNV-1a ハッシュとする。同じ名前のファイルを取り込み直しても、読書位置としおりを引き継ぐ。
3. フォルダから取り込んだときはフォルダを覚え（`sources.json`）、ファイルごとに「大きさ:更新日時」の署名を持つ。
   再スキャンは署名だけで差分を取り、中身のハッシュは取らない。
4. 保存は SQLite（Drift）ではなく JSON ファイルにする。元の Novelty の DB のスキーマとマイグレーションに手を入れず、
   上流の更新を取り込みやすくするため。

## 代替案

- **元のファイルを毎回読む**：保存領域は節約できる。ただし、元ファイルの移動・削除・権限の取り消しで読めなくなり、
  文字コードの判別も毎回走る → 却下
- **Drift のテーブルに入れる**：検索や並べ替えは楽になる。ただし、上流の DB のマイグレーションと衝突する → 却下
- **ID を中身のハッシュにする**：中身を直すたびに ID が変わり、しおりが外れる → 却下

## 結果

- 端末の保存領域を、本文のぶんだけ余計に使う（テキストなので小さい）。
- 同じ名前の別作品は、1つの作品として扱われる（フォルダ内では先に見つかったほうを採る）。
