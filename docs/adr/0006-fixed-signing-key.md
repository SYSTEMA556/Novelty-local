# ADR-0006: 署名の鍵を Secret に固定し、RSA 2048 にする

- ステータス: 採択
- 日付: 2026-11-19
- 範囲: フォーク Novelty-local のみ

## 背景

CI は release 署名の鍵をビルドのたびに `keytool -genkeypair` で作り直していた。Android は、入っているアプリと
署名の鍵が違うと上書きを拒む。そのため、新しい版を入れるたびにアンインストールが要り、本棚としおりが消えていた。

## 決定

1. 鍵を1つ作り、base64 にしてリポジトリの Secret `ANDROID_KEYSTORE_BASE64` に入れる（エイリアス `novelty`）。
   Secret が無いときだけ、従来どおりその場で作って警告を出す。
2. 鍵は **RSA 2048 / SHA256withRSA** とする。

## 経緯

最初は RSA 4096 / SHA384withRSA の鍵を作った。その鍵で署名した APK は、署名の検証（APK Signature Scheme v2）は
通ったが、Xiaomi の端末（HyperOS）に、何も入っていない状態からでも「パッケージが無効」として入らなかった。
それまで入っていた鍵と同じ RSA 2048 / SHA256withRSA で作り直したところ、入った。

## 代替案

- **鍵をリポジトリに入れる**：手間は無い。ただし公開リポジトリなので、誰でも同じ署名の APK を作れる → 却下
- **Actions のキャッシュに鍵を置く**：Secret が要らない。ただし、7日間使わないと消え、消えたら鍵が変わる → 却下

## 結果

- これ以降の APK は上書きで入り、本棚・しおり・設定が残る。
- 鍵を失くすと、次の版からまたアンインストールが要る。鍵の控えは利用者が持つ。
